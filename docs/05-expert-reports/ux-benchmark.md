# 정보 설계·UX 벤치마크 보고서

AI 평가자 1명(정보 설계·UX)이 비교 사이트 10곳(레퍼런스 사이트 포함)의 구조와 길이를 보고, 현재 사이트의 구조 문제 17건과 제안 구조(와이어프레임 포함), 권고 13건을 냈다. 문구는 평가하지 않았다(구조·위계·동선·상호작용·길이만).

## 읽기 전에

- **평가자는 AI다.** 사람의 의견이 아니며 점수는 AI의 판단이다. 평가는 2026-11-27 시점의 사이트(2차 문구 수정 직후)를 정지 화면 캡처와 소스 코드로 본 것이다. Edge(Chromium) 헤드리스에서만 확인했고 Safari, Firefox, 실제 터치, 스크린리더는 확인하지 않았다.
- **이후 사용자 피드백이 우선한다.** 사용자는 이 평가 뒤에 "처음 화면이 너무 AI스럽고 과하다", "이름이 너무 크게 나와서 거부감이 들었다", "밝은 게 더 좋아 보인다"고 말했다. 그래서 이름 글자를 줄이고 기본 테마를 라이트로 바꿨다. 이 문서의 제안 중 화려한 쪽(일러스트 히어로, 글로우, 큰 글자, 캔버스 연출)은 **보류 상태**다. 배경은 [01-context-and-decisions.md](../01-context-and-decisions.md), 보류 항목은 [08-backlog.md](../08-backlog.md)의 D·E 구역에 있다.
- **줄 번호 표기.** 근거 칸의 `css:15`, `main.js L120`, `index.html:52-64` 같은 표기는 평가 시점 파일의 줄 번호다. 이후 편집으로 어긋나므로 선택자·함수 이름으로 찾는다.
- **"제약 위반" 표기.** 웹폰트 파일 없음·의존성 없음은 작업자(AI)가 정한 제약이며 사용자 요구가 아니다. 도입하려면 사용자 승인이 필요하다([02-content-policy.md](../02-content-policy.md) 참고).
- **캡처 파일은 저장소에 없다.** 평가에 쓴 스크린샷에는 제3자 자료(레퍼런스 사이트, 레퍼런스 덱)가 섞여 있어 싣지 않았다. 원문의 캡처 파일명은 "스크린샷 캡처"로 바꿨다.
- **README 사본.** `README_*.md`, `stats.md`, `meta_*.json`은 공개 저장소에서 받은 원문 사본이며 `docs/sources/`에 둔다.

- 비교 사이트 높이는 1280 폭, 이 사이트는 1440 폭에서 쟀기 때문에 ±10% 오차가 있다. 벤치마크 10곳 중 8곳은 열어서 확인했고 2곳은 일부만 확인했다. 비교 대상의 주소는 모두 공개 주소다.
- 목표 길이(약 8,500~9,000px)는 설계 목표이며 구현 후 다시 재야 한다.

## 범위와 측정 방법

- **평가 범위**: 문구(카피)는 평가하지 않았다. 구조·위계·동선·상호작용·길이만 본다. findings 의 'finding N' 표기는 findings 배열 순서(1부터)를 뜻한다.

### 측정 메모

- 우리 사이트 수치: Edge 헤드리스 ?shot=1(정지 모드), 폭 1440, vh=900, 영어. 측정 스크립트는 저장소에 포함하지 않음. 정지 모드 문서 높이 15,473px, 모바일(390폭) 20,943px.
- 라이브 스크롤에서는 #principles 가 .pr-wrap{height:calc(var(--vh)*4)} (css/style.css:218)라서 3,600px 가 된다. 정지 모드는 771px 이다. 라이브 길이는 15,473 - 771 + 3,600 = 약 18,302px (산출값, 직접 측정 아님). 모바일은 20,943 - 618 + 4x844 = 약 23,700px (산출값).
- 비교 사이트 문서 높이는 Claude 브라우저 창 1280px 폭에서 JS(scrollHeight)로 직접 읽었다. 폭이 우리(1440)와 달라 +-10% 범위의 오차가 있다. 첫 로드 애니메이션 중 읽은 값은 없다.
- 웹 조회 검색어·URL 에는 사용자 개인 정보를 넣지 않았다. 사용한 도구: 웹 검색/페이지 추출(텍스트), 브라우저 창 캡처·DOM 측정.
- cassie.codes 는 열어 보니 개인 사이트를 닫았다는 안내 한 장만 있어(2026-11-06 취득본) 비교 대상에서 뺐다.

### 11. 상호작용 3종: Customize 패널, Ctrl+K 프로젝트 이동, 'Vision mode' 이스터에그

- **위험**: 기능이 늘수록 유지 부담과 접근성 점검 범위가 커진다. 이스터에그는 숨김 기능이라 발견성이 낮고, 키보드·스크린리더 사용자에게는 영향이 없어야 한다.
- **취향 적합(10점 만점)**: 높음 (Nazmus Customize/이스터에그 직접 대응)

### 12. 시그니처 비주얼: 번호 콜아웃 주석 + 렌즈 마스코트

- **우선순위**: P2
- **난이도**: L
- **내용**: (a) 히어로 증거 패널의 스크린샷 위에 번호 콜아웃(예: 1 PropertyGrid, 2 Layer, 3 OK/NG 근거)을 SVG 로 겹친다(레퍼런스 덱 A 장면 01 문법). (b) 렌즈/조리개 모양의 작은 마스코트를 SVG 로 그려 눈이 포인터를 따라가고 OK/NG 에 따라 표정이 바뀌게 한다(Nazmus 눈 캐릭터와 같은 계열).
- **이유**: 사용자 레퍼런스의 공통점은 '정보를 그림으로 말하는 정체성 요소'(레퍼런스 덱 A 장면 01 캐릭터와 콜아웃, 레퍼런스 덱 B 장면 01 별자리 canvas 와 레이더 카드)이다. 현재 사이트에는 그런 요소가 없다(finding 15).
- **방법**: (a)는 라벨 위치를 퍼센트 좌표로 지정한 SVG 오버레이로 S~M. (b)는 디자인 에셋(캐릭터 도안)이 먼저 필요하고 SVG 애니메이션은 M. 마스코트는 사용자가 원하는 캐릭터 방향을 정해야 한다.
- **위험**: 캐릭터는 취향·브랜드 판단이라 임의로 확정할 수 없다. 머신비전 전문가 신호를 약하게 만들 수 있어 작게 쓰고 끌 수 있게 한다.
- **취향 적합(10점 만점)**: 높음 (다만 사용자 확인 필요)
