# 아트 디렉터 보고서: 시각 방향과 디자인 평가

AI 평가자 1명(아트 디렉터 역할)이 사이트의 시각 언어, 색, 글꼴, 구조의 리듬을 평가하고 방향 3안(A·B·C)을 냈다. 이어서 D안(산업 모니터 다크) 보충 보고가 나왔고, **D안 보충 보고가 이 문서 앞쪽의 추천안보다 우선한다**(맨 아래 부록). 요약과 비교는 [04-design-evaluation.md](../04-design-evaluation.md)에 있다.

## 읽기 전에

- **평가자는 AI다.** 사람의 의견이 아니며 점수는 AI의 판단이다. 평가는 2026-11-27 시점의 사이트(2차 문구 수정 직후)를 정지 화면 캡처와 소스 코드로 본 것이다. Edge(Chromium) 헤드리스에서만 확인했고 Safari, Firefox, 실제 터치, 스크린리더는 확인하지 않았다.
- **이후 사용자 피드백이 우선한다.** 사용자는 이 평가 뒤에 "처음 화면이 너무 AI스럽고 과하다", "이름이 너무 크게 나와서 거부감이 들었다", "밝은 게 더 좋아 보인다"고 말했다. 그래서 이름 글자를 줄이고 기본 테마를 라이트로 바꿨다. 이 문서의 제안 중 화려한 쪽(일러스트 히어로, 글로우, 큰 글자, 캔버스 연출)은 **보류 상태**다. 배경은 [01-context-and-decisions.md](../01-context-and-decisions.md), 보류 항목은 [08-backlog.md](../08-backlog.md)의 D·E 구역에 있다.
- **줄 번호 표기.** 근거 칸의 `css:15`, `main.js L120`, `index.html:52-64` 같은 표기는 평가 시점 파일의 줄 번호다. 이후 편집으로 어긋나므로 선택자·함수 이름으로 찾는다.
- **"제약 위반" 표기.** 웹폰트 파일 없음·의존성 없음은 작업자(AI)가 정한 제약이며 사용자 요구가 아니다. 도입하려면 사용자 승인이 필요하다([02-content-policy.md](../02-content-policy.md) 참고).
- **캡처 파일은 저장소에 없다.** 평가에 쓴 스크린샷에는 제3자 자료(레퍼런스 사이트, 레퍼런스 덱)가 섞여 있어 싣지 않았다. 원문의 캡처 파일명은 "스크린샷 캡처"로 바꿨다.
- **README 사본.** `README_*.md`, `stats.md`, `meta_*.json`은 공개 저장소에서 받은 원문 사본이며 `docs/sources/`에 둔다.

- 이 보고서의 시안 파일은 [../design-proposals/README.md](../design-proposals/README.md)에 있다. 사용자는 아직 시안을 보지 못했고 선택하지 않았다.

## 평가 점수와 총평

- **최신성**: 6
- **시각 인터랙션**: 4
- **개성**: 3
- **사용자 레퍼런스 취향 적합**: 3
- **종합**: 5
- **요약**: 기술 구현(스크롤 연동 고정 구간, 선 그리기, 미디어 뷰어, 접근성 경로)은 최신식이지만 시각 언어는 2022~23년식 '다크 개발자 템플릿' 공식(근흑 배경 + Tailwind teal-400 단색 + 유리 알약 내비 + 'Hello, I'm' 대형 이름 히어로 + 숫자 카드 + 아이콘 카드)과 거의 일치한다. 머신비전이라는 정체성을 알려 주는 그림이 없고(히어로 괄호는 무작위 생성), 색에 의미가 없어 OK/NG·사용 가능/개발 중을 색으로 구분하지 못한다. 한국어 Windows인 이 PC에서 CDP로 확인하니 영문 제목을 포함한 모든 텍스트가 Malgun Gothic으로 렌더되고, 제목 자간이 서체에 비해 지나치게 좁다. 사용자 취향(일러스트·인포그래픽·역할이 있는 색 체계·의미 있는 모션)과의 거리가 가장 큰 항목은 '설명 도구로 쓰이는 일러스트'가 전혀 없다는 점이다. 추천은 B안(크림·남색·신호색 + 주석 달린 검사 장면 일러스트)이다.

## 사용자 취향 검증

- **검증한 주장**: 사용자 취향은 미니멀 모노톤 개발자 템플릿이 아니라 일러스트·인포그래픽·색 체계가 있는 풍부한 시각 언어와 의미 있는 모션이다.
- **판정**: 대체로 맞다. 단서 2개.

### 뒷받침하는 근거

- 레퍼런스 덱 A 장면 01: 캐릭터 일러스트의 부위마다 번호 말풍선이 제품 구성요소를 지시한다. 일러스트가 장식이 아니라 설명 도구다.
- 레퍼런스 덱 A 장면 08: 남색=기준·구조, 초록=이익·확정, 주황=경고·보류로 색이 의미를 갖고, 같은 색이 우측 카드(수치 카드)에 일관되게 쓰인다.
- 레퍼런스 덱 B 장면 01: 한 색조(보라) 안에서 사진·별자리 선·유리 카드·레이더 차트가 한 체계로 묶인다.
- 레퍼런스 사이트 캡처 3장: 호감 요소는 히어로 캐릭터, 로고가 붙은 기술 카드, 프로젝트 캐러셀 썸네일, 테마 전환·Customize 같은 개성 장치로 보인다(추정).

### 단서

- 레퍼런스 세 곳의 배경색이 크림 / 짙은 보라 / 근흑으로 서로 다르다. 취향은 특정 배경색이 아니라 '색이 의미를 갖는 체계'다.
- '풍부함'은 장식 추가가 아니라 설명 가능한 시각물이어야 한다. 이 사이트에서는 검사 장면 일러스트 + 프로젝트 번호 주석이 그 역할을 한다. 레퍼런스 사이트 자체는 다크 템플릿 구조(히어로 + 카드 캐러셀)라, 구조를 따라 하면 현재와 비슷한 결과가 된다.

## 발견 사항

### 1. identity / 전체

- **관찰**: 'AI가 만든 다크 개발자 템플릿' 구성요소가 거의 전부 일치한다:
  - (a) 근흑 배경 + Tailwind teal-400(#2dd4bf) 단색,
  - (b) 상단 유리 알약 내비(backdrop-filter),
  - (c) 'Hello, I'm' + 초대형 이름 + 알약 CTA 3개 히어로,
  - (d) 점 격자 + 스캔선 배경,
  - (e) 같은 크기 숫자 카드 4개,
  - (f) 아이콘 2x2 기술 카드,
  - (g) 점이 찍힌 세로 타임라인,
  - (h) 모든 블록에 blur + translateY 등장. 도메인(머신비전)을 알려 주는 시각 요소는 히어로 검출 괄호 하나뿐이고, 그마저 위치가 무작위라 내용과 연결되지 않는다.
- **근거**: css:15(#2dd4bf), :13(#090c0e), :56(유리 알약), :122-127(숫자 카드), :208-214(기술 카드), :233(타임라인), :48(blur 등장); index.html:52-64(히어로); 스크린샷 캡처
- **영향**: 높음

### 2. color / 전역 토큰 css:11-28

- **관찰**: 팔레트가 중립 6개 + 포인트 1개다. 포인트색 하나가 8가지 역할(인사말 .hello, 한글 이름 .kname, 번호 .no, 소제목 .sub, 'Get it' 라벨, 상태 칩 .chip.st, 코드 키워드 .k, 원칙 현재 줄 .cur)에 반복돼 '상태'도 '링크'도 '강조'도 구분해 주지 못한다. 합격/불합격이 핵심인 제품군인데 OK/NG를 색으로 말할 수 없다(텍스트에는 OK/NG가 반복된다).
- **근거**: css:82, :88, :113, :134, :143, :147, :177, :224; index.html:127(OK/NG 근거), :208(5장 통과 3장 NG 캡션)
- **영향**: 높음

### 3. color / 상태 칩 index.html:131,188,240,293,333,379

- **관찰**: '사용 가능', '개발 중', '소스 공개', 'VS Marketplace'가 모두 같은 .chip.st(청록 테두리·청록 글자)다. '사용 가능'과 '개발 중'(Machine Studio)을 시각으로 구분할 수 없다.
- **근거**: css:143; index.html:131(Usable), :293(Active development), :333(Source available), :379(VS Marketplace)
- **영향**: 중간

### 4. color / 카드·프레임 면 분리

- **관찰**: 다크 카드(#12181c)와 배경(#090c0e)의 명도 대비가 1.10:1이라 구조 전부가 1px 반투명 선에 의존한다. 어두운 앱 스크린샷이 어두운 프레임 안에 놓여 윤곽이 묻힌다. 같은 스크린샷이 라이트 테마에서는 또렷하게 분리된다 — 어두운 UI 캡처는 밝은 바탕에서 더 잘 보인다는 뜻이다.
- **근거**: 스크린샷 캡처(다크, 프레임 경계 흐림) vs 스크린샷 캡처(라이트, 또렷); css:13(--bg, --card), :151(.frame 테두리)
- **영향**: 중간

### 5. theme / 라이트 테마

- **관찰**: 라이트가 다크의 기계적 반전이다(배경 #f5f7f7 차가운 회백 + 청록 #0b766f). 라이트만의 분위기·질감·재질이 없다. 대비는 충분하다(accent 5.09:1).
- **근거**: css:20-28; 스크린샷 캡처
- **영향**: 낮음

### 6. theme / 시각 트렌드 대비(판단, 미검증)

- **관찰**: 어휘가 2022~23년 'Linear/Vercel식 다크 + 글래스 + 스포트라이트'에 머물러 있다. 2025~26년 포트폴리오·제품 사이트에서 두드러진 요소 — 따뜻한 종이색 바탕, 역할이 정해진 스팟 컬러 2~3개, 손으로 그린 듯한 주석 일러스트·스티커, 모노 인덱스 번호, 스크롤 연동 서사, 가변 굵기 타이포 — 중 모노 인덱스(.no)와 스크롤 고정 원칙 구간만 있다. 트렌드 판단은 조사 없이 아트 디렉터 관점의 추정이다.
- **근거**: style.css 전체; index.html 구조
- **영향**: 중간

### 7. type / 글꼴 스택 css:7

- **관찰**: 'ui-sans-serif,system-ui,"Segoe UI","Pretendard","Malgun Gothic"...'에서 system-ui가 먼저 매칭되고, 한국어 로캘 Windows에서 system-ui는 Malgun Gothic이다. 이 PC에서 CDP로 확인: 영문 'Noah Choi'(h1.name)와 직함(.role 43글리프), 원칙(.pr li 69글리프)까지 전부 Malgun Gothic이다(en·ko 모두). (글꼴 시험 화면, 저장소 미포함)에서 사이트 스택 행 = system-ui 행 = Malgun Gothic 행이고 Segoe UI 행과 다르다. Malgun은 Regular/Bold 두 굵기뿐이라 weight 800은 Bold로 대체된다. 'Pretendard'는 이 PC에 설치돼 있지 않고(레지스트리 확인) 방문자 대부분도 그럴 것이라 사실상 효과가 없다. 같은 사이트가 방문자 OS마다 다르게 보인다(macOS=SF, 영문 Windows=Segoe UI, Android=Roboto 추정 — 미확인).
- **근거**: css:7; (글꼴 시험 화면, 저장소 미포함); 측정 스크립트(저장소 미포함) 출력(CSS.getPlatformFontsForNode); 레지스트리 글꼴 목록(Pretendard 없음, Segoe UI·Segoe UI Variable·Bahnschrift·Noto Sans KR 있음)
- **영향**: 높음

### 8. type / 제목 자간

- **관찰**: 서체 대비 음수 자간이 과하다: .name -.055em, .ttl -.045em, .pull p -.03em, .pr li -.03em. 캡처에서 'Overview'(rv, ie), 'Releases', 원칙 줄 'Preserve evidence.'의 글자가 붙는다. 한국어 모드의 리셋은 .cue/.ttl.sm/.sub/.road dt/.get .gl에만 걸려 있어, .ttl·.name·.pull·.pr li·.big에는 한글에도 음수 자간이 그대로 적용된다('프로젝트' 획이 맞닿음).
- **근거**: css:83, :108, :117, :222, :250, :91(KO 리셋 범위); 스크린샷 캡처
- **영향**: 높음

### 9. hierarchy / 히어로 첫 화면

- **관찰**: 이름 216px 대비 직함 24px로 약 9:1이다. 정체성을 말하는 유일한 문장(직함)이 가장 약하다. 화면 오른쪽 약 25~30%는 빈 캔버스이고 머신비전을 보여 주는 이미지가 없다. 첫 프로젝트 스크린샷은 문서 y=2480px(1440x900에서 약 2.8화면 아래)에서 처음 나온다. 3번째 CTA('Visual Studio Marketplace' + 부제)는 긴 알약이라 주 CTA(GitHub)와 경쟁한다.
- **근거**: 스크린샷 캡처; css:83, :92; index.html:60-64; 측정값 절의 ‘첫 프로젝트 스크린샷 시작 위치(px)’
- **영향**: 높음

### 10. layout / 섹션 리듬

- **관찰**: 모든 섹션이 같은 배경, 같은 머리(.ttl 2.6~5.5rem + 청록 밑줄 + 회색 meta), 같은 상하 여백(clamp(72px,9vw,120px))이다. 배경·스케일·밀도 변화가 없고, 리듬을 깨는 것은 Principles 핀 고정 하나뿐이다. Projects(5,659px)와 Releases(3,449px)가 문서 15,473px의 약 59%를 차지하는데 둘 다 같은 행/카드 반복이다(정지 모드 측정).
- **근거**: css:106-111; 측정값 절의 ‘섹션 시작 위치(px, 영어)’; 여러 스크린샷 캡처의 동일한 머리 구성

## 추천안(첫 평가 기준)

- **이름**: B. Blueprint Cream (크림·남색·신호색 인포그래픽)
- **이유**: 근거 5가지.
  - (1) 사용자가 가장 직접 만든 자료(레퍼런스 덱 A: 크림 + 남색 + 초록·주황, 번호 말풍선이 붙은 주석 일러스트)와 가장 가깝고, 일러스트를 '설명 도구'로 쓰는 취향의 핵심을 반영한다.
  - (2) 색이 검사 장비의 판정 언어(OK 초록 / NG 주황 / ROI 호박)와 같아, 팔레트 자체가 머신비전 정체성이 되고 상태 칩·주의 note·브래킷에 한 규칙으로 일관된다. A·C안의 포인트색은 도메인과 무관하다.
  - (3) 현재 가장 큰 시각 결함인 '첫 화면에 머신비전이 안 보임'을 점선 청사진 장비 + 실선 소프트웨어라는 시각 문장으로 풀고, 이것이 사이트 주제('장비가 준비되기 전에 먼저 만든다')와 정확히 일치한다.
  - (4) 어두운 앱 스크린샷이 크림 위 남색 모니터 프레임에서 분리된다는 점을 현재 라이트 캡처(스크린샷 캡처)로 확인했다.
  - (5) 기존 모티프(괄호, 스캔, 점 격자, 번호)를 버리지 않고 승격한다. 위험은 일러스트 유지 비용과 장난스러움이며, 이는 평면·절제된 선·마스코트 없음으로 관리한다. 글꼴은 1단계에서 시스템 스택 수정(P0, 웹폰트 없음)만 하고 Barlow는 승인 뒤 P2로 둔다. 선택은 아트 디렉터 판단이며 취향이 달라지면 C안(보라)도 같은 토큰 구조로 바꿀 수 있다.

- **최소 변경 경로**: 토큰 교체 css:11-19(S) -> 글꼴 파일·스택 css:7(S~M) -> 상태 칩 톤 css:143(S) -> kicker css:109,113(S) -> 알약 탭(S) -> 글로우로 hero.js 대체(S) -> Overview 재색 + 패킷(M) -> 히어로 장면(L) -> 미디어 프레임 rim(S).

### 2. 취향 해석 갱신
- **검증 결과: 맞고 더 강해졌다.** 세 자료의 배경은 크림 / 보라 / 근흑으로 제각각인데, 공통점이 4가지다. (1) 색에 역할이 있다: 레퍼런스 덱 A 초록·주황, 레퍼런스 덱 C mint/blue/amber/red와 "한 장에 accent 하나"(base.css:23), 레퍼런스 덱 B는 라벤더 하나를 절제해 쓴다. (2) 설명하는 그래픽: 주석 일러스트, 별자리·레이더, 신호선·타일·파이프라인. (3) 위치·진행 가구: 레퍼런스 덱 A 점선 진행 막대 + `→ 01`, 레퍼런스 덱 B 상단 막대 + `2 / 4` + PART 태그, 레퍼런스 덱 C 상단 막대 + 알약 탭 + `08 / 18`. 덱 관행일 수 있어 사이트에는 절제해 옮긴다. (4) 의미 있는 모션(마스크 와이프, 선 그리기, 패킷, 카운트업).
- **정정 1**: 어두운 배경이 3개 중 2개(레퍼런스 사이트까지 4개 중 3개)다. 크림이 취향이라는 근거는 약하다. JSON의 B 추천 근거 (1) "사용자가 가장 직접 만든 자료(레퍼런스 덱 A)와 가장 가깝다"는 사용자가 만든 자료인지 확인한 적 없는 가정이라 철회한다.
- **정정 2**: 레퍼런스 덱 C이 웹폰트(base64)와 GSAP를 이미 쓴다. "의존성·웹폰트 금지"는 사용자 요구가 아니라 우리 쪽 제약이었다. 기존 평가의 "제약 위반" 표기는 "승인 필요 항목"으로 완화한다.

### 4. 갱신된 추천: 단정하지 않는다
- 정체성·개성·가독성은 B가, 변경량·한글 타이포·사용자 자산(토큰·폰트) 연속성은 D가 앞선다. 가중치는 내 판단이라 시안 3장으로 사용자가 고르는 것이 맞다.
- 사이트에 다크/라이트 토글이 이미 있어 이중 테마가 가능하다: 라이트 = B 팔레트, 다크 = D 팔레트, 의미 토큰(--ok/--ng/--roi/--in)과 히어로 SVG 한 벌을 공유하고, D의 모노 크롬(kicker·알약 탭·카운터)은 양 테마에 쓴다. D의 파이프라인 + 모니터 장면은 Overview로 보낸다. `docs/design-proposals/concept-b-in-d-tokens.png`가 같은 장면이 D 토큰에서도 성립함을 정적 렌더로 보여 준다. 비용은 팔레트 2벌 대비 검증과 폰트다.
- **한 줄**: 테마 기본값은 사용자가 시안으로 고르고, 그 전에는 둘에 공통인 기반(의미 토큰, 글꼴 스택, 상태 칩 색, kicker·알약 탭, 미디어 rim 프레임)부터 진행하며, 선택이 없으면 이중 테마(라이트 B / 다크 D, 히어로 장면 공유)를 기본으로 한다.

### 5. 미검증
- 레퍼런스 덱 C 캡처가 애니메이션 도중 프레임이라 본문 슬라이드는 코드로만 판단했다. D 시안은 정적 1장이고 모션·패킷은 코드로만 구상했다.
- 시안 글꼴은 Segoe UI/Cascadia로 대체 렌더했다. Pretendard·JetBrains Mono 실제 렌더와 사이트 용량은 덱 실측치를 외삽한 추정이다.
- 이중 테마는 정적 렌더 1장으로만 확인했고 양 테마의 대비·스크린샷 가독성은 실측하지 않았다.
- mint=사용 가능, amber=개발 중 매핑, 알약 탭 섹션 구분, 06 프로브와 모니터의 장식 연결(Overview에 없는 관계)은 사용자 확인이 필요하다.
- GSAP 라이선스·용량은 확인하지 않았다(필요 없다는 판단).
