# 디자인 평가와 개선안

> **먼저 읽을 것: 이 평가의 지위**
>
> - 평가자는 **AI 에이전트 4명**(아트 디렉터, 인터랙션·모션 디자이너, 정보 설계·벤치마크, 프로젝트 쇼케이스 기획자)이다. 사람의 의견이 아니고, 모션은 정지 화면과 코드로 판단했다. 아래 점수는 모두 AI 평가자의 것이다.
> - 사용자는 이 평가 뒤에 처음 화면을 보고 **"너무 AI스럽다, 과하게 화려해서 반감이 든다"**고 했고, 원인을 묻자 **"이름이 너무 크게 나와서 거부감이 들었다"**, 이어서 **"밝은 게 더 좋아 보인다"**고 했다. 그래서 히어로 이름 글자를 줄이고 기본 테마를 라이트로 바꿨다([01-context-and-decisions.md](01-context-and-decisions.md)).
> - 따라서 **이 문서의 제안 중 화려한 쪽(일러스트 히어로, 글로우, 큰 글자, 캔버스 연출 등)은 보류 상태**다. 사용자는 아래 시안을 아직 보지 못했고 선택하지 않았다([design-proposals/README.md](design-proposals/README.md)). 이 문서의 제안을 사용자 승인 없이 사이트에 적용하지 않는다.
> - 평가 대상 사이트는 2026-11-27 시점(2차 문구 수정 직후, 다크 기본·큰 이름 상태)이다. **현재 사이트는 이 평가 때와 다르다**(라이트 기본, 이름 축소, 버그 수정 진행). 진단 중 "코드로 확인한 결함 4건"의 처리 상태는 [08-backlog.md](08-backlog.md)에서 확인한다.
> - 상세 근거와 원자료 요약은 [05-expert-reports/](05-expert-reports/)에 있다.

## 1. 결론

현재 사이트는 **기법은 최신이지만 구성은 "다크 개발자 템플릿"이고, 인터랙션은 장식과 썸네일 갤러리 수준**입니다. 사용자가 준 레퍼런스(일러스트·인포그래픽·의미 있는 색과 모션)와는 거리가 있습니다.

## 2. 사용자 취향 레퍼런스 해석

| 레퍼런스 | 배경 | 핵심 어휘 |
|---|---|---|
| 레퍼런스 사이트(nazmussayad.com) | 근흑 다크 | 직접 그린 캐릭터 일러스트, 입자 캔버스, 프로필 사진, 로고 기술 카드, 프로젝트 카드 캐러셀, 타임라인, 테마 전환, Customize 패널(Ctrl+.), 이스터에그 |
| 레퍼런스 덱 A | 크림·남색 | 직접 그린 캐릭터 일러스트 + 번호 말풍선 지시선, 워터폴 차트, 점선 진행 막대, 초록·주황 포인트 |
| 레퍼런스 덱 B | 짙은 보라 | 사진 + 별자리 네트워크 선, 유리 카드 안 레이더 차트 |
| 레퍼런스 덱 C (추가) | 짙은 남흑 | mint·blue·amber·red 상태색(구간마다 주색 변경), 모노 폰트 kicker, 알약 단계 탭, 신호선 SVG 애니메이션, 타일 격자, 완결 문장형 제목, **Pretendard·JetBrains Mono 내장, GSAP 사용** |

- 배경색은 제각각이고 공통점은 **색이 의미를 갖는 체계**와 **다이어그램·일러스트로 설명하는 언어**입니다. 미니멀한 모노톤 템플릿이 아닙니다.
- 덱 C에서 확인한 사실: 사용자는 웹폰트를 파일에 내장하고 GSAP도 쓴 적이 있습니다. 그렇다면 "의존성·웹폰트 금지"는 사용자 요구가 아니라 이번 작업에서 작업자(AI)가 정한 제약이었습니다. 허용 여부를 아래 "결정할 것"에 넣었습니다.
- 덱 C는 본문 슬라이드를 애니메이션이 끝난 상태로 캡처하지 못해(GSAP 진행 중 프레임) 본문 구성은 코드 구조로만 판단했습니다.

## 3. 진단 (교차 검증된 순서)

### 4-2. 구조 (정보 설계·벤치마크 제안)

내비(+ Email 버튼) → 히어로(증거 패널 + CTA + 통계 스트립) → Work(6카드, 클릭하면 상세 `<dialog>`) → System(구성도, 노드를 링크로) → Principles(고정 길이를 약 2.2×vh로) → About & Experience(경력 블록 자리) → Releases(최근 5개만, 나머지 접기) → Contact.
목표 길이는 약 8,500~9,000px(현재의 절반 수준, 설계 목표이고 구현 후 재측정 필요)입니다.

작성 AI가 합친 제안: 아트 디렉터의 "주석 일러스트 히어로"와 UX의 "증거 클립 히어로 패널"은 같은 자리를 노리므로, **일러스트의 모니터 프레임 안에서 증거 클립이 재생되고 번호 말풍선 6개가 프로젝트로 이동하는 링크**가 되게 합치는 것을 권합니다.

### 4-5. 영상·GIF 규격

- 카드·히어로: mp4(H.264, muted loop playsinline) 6~12초, 1280×720, 15 fps, 1MB 이하 + 결과가 채워진 프레임의 poster.webp. 상세 뷰어에서만 GIF 허용.
- 실측: 지금 GIF 5개 4.85MB를 같은 해상도 mp4로 바꾸면 1.26MB(화질은 눈으로 검수하지 않음). 2D mp4를 앞 12초, 1280 폭으로 줄이면 112KB. 사이트 전체 9.35MB → 약 3.5MB(계산값).
- 이 사이트는 이미 `<video>` 경로와 "보일 때만 재생" 규칙이 있어서 mp4 교체는 HTML 수정 수준입니다.

## 6. 결정할 것 (사용자)

1. **비주얼 방향**: B(크림·남색·판정색 일러스트), D(산업 모니터 다크, 마지막 레퍼런스 계열), A(현재 개선), C(보라). 아래 7절의 D안 시안을 B안과 나란히 보고 고르세요.
2. **웹폰트·라이브러리 허용**: Pretendard·JetBrains Mono 서브셋 내장(OFL), GSAP 사용 여부. 허용하지 않으면 시스템 글꼴 스택과 순수 CSS/JS로 갑니다.
3. **히어로에 쓸 대표 클립**: 어느 프로젝트로 할지(UX 제안은 3D Studio 로트).
4. **마스코트·프로필 사진 사용 여부**(레퍼런스는 사진과 캐릭터를 씀). 숙련도 배지·퍼센트는 근거 있는 값이 없으면 만들지 않습니다(자기평가는 새 주장이 됩니다).
5. **Overview에 Raw Buffer Visualizer를 넣을지**(현재 도식에는 없음).
6. **경력 블록과 이력서 링크**(평가자 8명 중 다수가 첫째로 지적한 항목, [06-persona-evaluation.md](06-persona-evaluation.md)).
7. **색 의미 매핑 동의**(초록=OK·사용 가능, 주황=NG·주의, 호박=ROI).

## 7. D안(Industrial Monitor Dark) 시안

시안: [스크린샷 캡처](스크린샷 캡처), [스크린샷 캡처](스크린샷 캡처)(B의 일러스트를 D 팔레트로 렌더한 이중 테마 확인용), [concept-d-industrial-dark.html](design-proposals/concept-d-industrial-dark.html). 상세 설계는 [art-direction.md의 부록](05-expert-reports/art-direction.md).

**취향 해석 갱신 (아트 디렉터가 정정)**: 4개 레퍼런스 중 3개가 어두운 배경이라 "크림이 취향"이라는 근거는 약합니다. 첫 평가의 B안 추천 근거("사용자가 가장 직접 만든 자료와 가장 가깝다")는 확인한 적 없는 가정이라 철회했습니다. 공통점은 배경색이 아니라 (1) 색에 역할이 있고 (2) 설명하는 그래픽이 있고 (3) 위치·진행 표시 장치(점선 진행 막대, 단계 탭, `08 / 18`)가 있고 (4) 모션에 의미가 있다는 것입니다.

**D안 요약**: 레퍼런스 덱 C의 토큰 그대로(bg #070B10, mint #4ADE80, amber #FBBF24, red #F87171, blue #60A5FA). Pretendard + JetBrains Mono 서브셋(OFL)은 2+2굵기로 약 390KB로 추정합니다(레퍼런스 덱 C에서 실측한 굵기당 174~178KB와 21KB를 외삽). 신호선은 GSAP 없이 기존 `pathLength` + dashoffset으로 됩니다. 알약 단계 탭은 현재 내비를 CSS 몇 줄로 바꿔 쓸 수 있습니다.

| 기준 | B Blueprint Cream | D Industrial Monitor Dark |
|---|---|---|
| 사이트의 메시지("장비가 준비되기 전에 먼저 만든다") | **우세**: 점선 장비 위의 실선 소프트웨어가 그 문장 자체 | 시스템 화면 느낌은 정확하지만 이 메시지는 그림이 말하지 못함 |
| 사용자 취향 3개 레퍼런스 | 덱 A에 강함, 나머지는 색 의미만 | 덱 C에 거의 일치, 덱 B 부분. 동률로 봄 |
| 현재 사이트에서의 변경량 | 큼(테마 반전, 새 프레임, 일러스트) | **중간**(토큰·글꼴·크롬 교체, 청록→mint라 연속성 높음) |
| 개성(템플릿 느낌) | **우세**: 다크 개발자 공식에서 벗어남 | 약함: 근흑+녹색은 흔한 조합이라 다색 문법·모노 라벨 같은 작은 단서에 의존 |
| 어두운 스크린샷 가독성 | **우세**: 남색 프레임 대 크림 약 15:1 | 카드 채움 대비 1.15:1로 현재(1.10:1)와 사실상 같음. 테두리·글로우로 보완하지만 근본 해결은 아님 |
| 일러스트 확장성 | **우세** | 다이어그램·타일·신호선은 강하고 그림형 장면은 B의 장면을 가져와야 함 |
| 한글 타이포 | 약함(큰 한글 제목이 시스템 글꼴) | **우세**: Pretendard가 한글 제목까지 통일 |
| 승인 필요 | 웹폰트 약 35KB(추정, 선택) | 약 390KB(추정). 레퍼런스 덱 C이 이미 내장해서 허용될 가능성 높음 |

**아트 디렉터의 갱신된 추천: B와 D 중 하나로 단정하지 않습니다.** 둘에 공통인 기반부터 진행합니다(의미 색 토큰, 글꼴 스택, 상태 칩 색 구분, 모노 kicker와 단계 탭, 미디어 테두리 프레임). 테마 기본값은 사용자가 시안 3장(concept-b-hero-cream, concept-d-industrial-dark, concept-b-in-d-tokens)으로 고르게 하고, 선택이 없으면 **이중 테마**(라이트 = B 팔레트, 다크 = D 팔레트, 히어로 일러스트 공유)를 기본으로 합니다. 이 사이트에는 이미 다크/라이트 토글이 있어서 가능한 구성이고, `스크린샷 캡처`가 같은 일러스트가 다크 팔레트에서도 성립함을 보여 줍니다.

D안의 솔직한 약점: 어두운 스크린샷 문제는 B가 근본적으로 풀고 D는 보완하는 수준입니다. 이중 테마의 대비·스크린샷 가독성은 정적 렌더 한 장으로만 확인했고 실측하지 않았습니다. 시안 속 06 프로브와 모니터를 잇는 선은 장식이며 Overview에 없는 관계입니다.
